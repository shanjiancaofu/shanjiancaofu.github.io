有了时钟中断和内存分配后，内核就能为多个执行流准备独立栈，并在时间片到期或线程主动阻塞时切换任务。`ffz-os` 使用一页内存同时保存线程控制块和内核栈，这让许多关键机制变得直观。

## 一页内存中的 PCB 与栈

每个内核线程申请一个 4 KiB 页，`task_struct` 放在页的低地址，内核栈从页顶向下增长：

```text
高地址  +------------------+
        | 内核栈 ↓          |
        |                  |
        | 空闲空间          |
        |                  |
低地址  | task_struct/PCB  |
        +------------------+
```

由于页大小是 4096 字节，获取当前栈指针 ESP 后，将低 12 位清零即可得到当前线程的 PCB 地址：

```cpp
return (task_struct *)(esp & 0xfffff000);
```

这种技巧简单高效，但前提是每个线程的内核栈严格位于自己的对齐页中，并且不能发生栈溢出。

## 新线程第一次如何运行

创建线程时，内核在栈顶预留中断栈和线程切换栈，把入口设置为 `kernel_thread`，再保存真正的函数与参数。

当 `switch_to` 第一次切换到该线程时，恢复出来的返回地址会进入 `kernel_thread`。它先打开中断，再调用用户指定的线程函数。这样“第一次启动”和“以后从现场恢复”可以使用同一套切换机制。

## 就绪队列与所有线程队列

内核维护两条链表：

- `thread_ready_list` 保存可以获得 CPU 的线程；
- `thread_all_list` 保存系统中所有线程，用于查询和管理。

正在运行的线程不在就绪队列中。时间片耗尽时，调度器把它放到队尾并重置 `ticks`，再取队首线程运行。这是一种简单的轮转策略，优先级同时决定时间片长度。

## 阻塞与主动让出 CPU 的区别

`thread_yield()` 会把当前线程重新加入就绪队列，表示它仍然可以运行，只是主动把机会让给其他线程。

`thread_block()` 则把状态改为 `BLOCKED`、`WAITING` 或 `HANGING`，不再进入就绪队列。直到某个事件调用 `thread_unblock()`，它才会重新获得调度资格。

当就绪队列为空时，内核唤醒 idle 线程。idle 在线程被调度后执行 `sti; hlt`，让 CPU 等待下一次中断，而不是无意义地忙循环。

## 信号量如何让等待者睡眠

值为 1 的信号量可以实现互斥。`sema_down()` 在关中断的保护下检查值：若资源不可用，就把当前线程加入等待队列并阻塞；被唤醒后再次检查条件。

```text
down
 ├── value=1：减为 0，继续运行
 └── value=0：加入 waiters，阻塞

up
 ├── 唤醒一个 waiter
 └── value 加 1
```

使用 `while` 而不是 `if` 很重要，因为线程从阻塞中恢复后仍应重新确认条件。

## 在信号量之上封装可重入锁

锁内部使用初值为 1 的信号量，同时记录持有者与重复获取次数。如果当前线程再次获取自己持有的锁，只增加计数；释放时计数归零才真正执行 `sema_up()`。

这使同一线程可以嵌套进入使用同一把锁的代码，但并不自动解决不同锁之间的死锁。锁顺序、持锁时间以及能否在持锁时阻塞，仍需要调用者设计。

## 调度问题要沿事件链排查

线程不切换时，可以按以下顺序检查：时钟 IRQ 是否打开、tick 是否更新、当前线程的时间片是否递减、就绪队列是否有任务、状态切换是否在关中断区完成、汇编上下文是否正确保存。

从中断到调度，再到同步原语，这些模块不是孤立的。亲手实现一次后，会更容易理解上层 RTOS 或 Linux API 背后的代价和约束。
